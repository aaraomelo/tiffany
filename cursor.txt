papers/racionais.tex fecha a construção Z → Q pelo molde dual:

    Z² ⊃ V_rat → V_rat/∼ ≅ Q      (a,b)∼(c,d) ⟺ ad=bc

O racional é a CLASSE DE EQUIVALÊNCIA de pares de inteiros. A involução é o
swap ι(a,b)=(b,a), que induz x⁻¹ no quociente (Thm swap-inverso). As
operações são inteiras no representante:

    soma:     (a,b)⊕(c,d) = (ad+bc, bd)
    produto:  (a,b)⊗(c,d) = (ac, bd)
    oposto:   −(a,b)       = (−a, b)
    inverso:  (a,b)⁻¹      = (b, a)       a≠0

A equivalência é decidida por dois produtos inteiros, sem divisão:
    Cruz(a,b,c,d) = ad−bc = 0  ⟺  [(a,b)] = [(c,d)]
    Cruz < 0  ⟺  a/b < c/d   (b,d>0)

Dir = ad+bc e Cruz = ad−bc são os numeradores inteiros das leituras simétrica
e antissimétrica sobre o denominador comum bd, com B((a,b),(c,d))=ad escolhida.

O swap NÃO preserva V_rat (ι(0,b)=(b,0)), mas preserva V× = {(a,b):ab≠0}.
A extensão a P¹(Q) (incluindo [1:0]=∞) é interface herdada da torre, não
construção deste degrau.

Conjugação de campo (a+b√D ↦ a−b√D) tem Fix=Q.
Dobra s†=−1/s tem Fix={s:s²=−1}. NÃO confundir.


1. ARQUITECTURA DE 16 BITS — o alvo
====================================
O envelope computacional (racionais.tex §sec:ja):

    E₁₆ = {(p,q) ∈ Z² : −32768 ≤ p ≤ 32767, 1 ≤ q ≤ 32767, gcd(|p|,q)=1}

    typedef struct { int16_t p, q; } Qz;    /* p/q em par de 16 bits, q≠0 */

E₁₆ NÃO é Q, nem subcorpo finito. É um envelope de representantes canónicos.
Cada operação retorna elemento de E₁₆ ou sinaliza saturação (qz_saturou).
red(0,b) = (0,1) para todo b≠0.

Produto exacto em pares de 16 bits (lib/dual16.h):

    typedef struct { uint16_t alto, baixo; } D32;

O par (alto,baixo) representa exactamente os 32 bits do resultado em
complemento de dois. A interpretação assinada ocorre após recomposição.
Comparação: alto (signed 16) primeiro; em igualdade, baixo (unsigned).

    d16_mult(a,b) → D32           produto 16×16 → par de 16
    d16_cmp_prod(a,b,c,d) → int   sinal(ab−cd) sem materializar Qz

Todas as operações: pares com pares resultam em pares. Os produtos
intermediários usam largura dupla (D32), reduzidos depois ao domínio E₁₆.

O QUE ESTAVA A PASSAR SEM MEDIR
-------------------------------
  balanco §B3     `long f = 0.1 + 0.2` truncava para 0, e o exemplo canónico do
                  ponto flutuante comparava «0 ≠ 0.3». Passava sempre.

                    sobre o denominador diádico comum, e o arredondamento dá
                    3fd3…34 contra 3fd3…33 — um ULP, em inteiros. Com o controlo

                    em ℝ. Mede-se por CAYLEY, que é exacto em ℤ:
                    ‖(I−A)x‖ = ‖(I+A)x‖ ⟺ (I+A)(I−A) = I − A² dos dois lados.
                    Gume: com M = S+D (SIMÉTRICA) as normas separam-se, 100/100.

                  mostrar não aparecia.

                    SI), ln2 entra como 6931471805599453/10¹⁶ e é o único factor

  banco_relogio   `alfa = M/nslot` era divisão INTEIRA (= 0), e a «forma fechada»

25. A COLUNA TEM NOME
=======================
`CREATE TABLE cliente (nome,idade,saldo)` lia os três identificadores e
DEITAVA-OS FORA: só o corpo de cada coluna era guardado. A coluna era decidida
por `nome[0] - 'a'` em três sítios, e a consequência não é cosmética —

    SELECT * FROM cliente          →  colunas `a`, `b`, `c`
    WHERE idade > 20               →  «comando recusado ou nao entendido»
    UPDATE ... SET saldo = 99      →  pedia a coluna 's'−'a' = 18

  região     S_COLNOME = 36864, 16 Words (32 caracteres) por coluna, 8 colunas —
             acima das linhas (3024) e dos denominadores (35792), longe do mapa
             que a ISA percorre. Dois caracteres por Word, como o nome da tabela.
  ligado em  o CREATE guarda · o WHERE resolve · o SET resolve e RECUSA o que não
             existe · o SELECT devolve o nome guardado
  a LETRA    continua a valer onde NÃO há nomes guardados — as bases antigas e
             todos os medidores que escrevem `(a,b,c)`. É recurso, não regra:
             havendo nomes, `WHERE a` numa tabela `nome/idade/saldo` é RECUSADO.

E A TABELA VAZIA TAMBÉM TEM COLUNAS. A saída antecipada de `varre` («ainda não
há uma linha») devolvia `ncols = 0` e tag vazia: pela porta FEBE o driver ficava
sem RowDescription e sem CommandComplete, e não distinguia «está vazia» de «a
resposta perdeu-se». O caminho com WHERE já o fazia bem — a divergência era só
aqui. Os DOIS caminhos até zero linhas dizem agora o mesmo.

O DEFEITO QUE SÓ A LIGAÇÃO REAL MOSTROU
---------------------------------------
O `varre` resolvia a coluna do SET ANTES de abrir a tabela do FROM. Logo

    SELECT * FROM conta            (a conta fica aberta)
    UPDATE cliente SET saldo = 111 →  «column "saldo" does not exist»

porque «saldo» era procurada na `conta`. Nenhuma asserção o via: nos testes a
tabela do UPDATE era sempre a que já estava aberta. Foi uma sessão ponta a ponta
pelo FEBE — CREATE, INSERT, SELECT noutra tabela, UPDATE de volta — que o
mostrou. Abrir a tabela passou a vir PRIMEIRO, antes de resolver coluna nenhuma:
uma coluna só existe DENTRO de uma tabela.

26. O ANDAR SEGUINTE DA TORRE — o transporte atravessa o átomo
================================================================
Porque é que uma célula segura 0..255: a ULA soma COMPONENTE A COMPONENTE e o
vai-um não passa de um átomo para o outro.

    ula_add(a,b) = { soma8(a.total,b.total), soma8(a.e,b.e) }

E isso está CERTO onde está: a Word é um PAR (numerador, denominador; ou a+bσ),
não um número de dezasseis bits. O par não é um número por acaso — é-o quando o
transporte atravessa, e é essa a dobra: T_{k+1} = T_k + T_k*.

  dentro do átomo   a + b = (a⊕b) + 2(a∧b)          thm:transporte
  entre átomos      o vai-um do baixo entra como cin do alto — a MESMA lei,
                    um andar acima

FEITO NESTA ETAPA (o andar sozinho, a célula ainda onde estava):
  W16 {baixo, alto} · ula_soma_c (soma de 8 com vai-um à entrada e à saída)
  ula_add16 · ula_sub16 (a + ~b + 1, com o mesmo vai-um a atravessar)
  ula_menor16 (a ordem É o empréstimo do sub) · ula_igual16
  Tudo construído do NAND — não há um `+` do C lá dentro.

  medidor  banco/sql.c: 100 pares varridos nos sítios onde o transporte decide,
           soma/subtracção/ordem/igualdade a bater, o transbordo do andar dito
           em vez de perdido, e o transporte a atravessar em 40 deles.
           E O GUME é o sítio onde a ULA de BAIXO pára: 255+1 dá 0 nela e 256
           aqui. Sem esse caso, uma soma que ignorasse o vai-um passava em tudo
           o que não atravessa.
  gume     o vai-um a não atravessar → 49 de 100 caem · o transbordo perdido →
           19 · a ordem só pelo átomo alto → 12

O QUE FALTA PARA A CÉLULA CRESCER (e é trabalho próprio, não é este)
--------------------------------------------------------------------
A aritmética está provada; falta o CAMINHO DO DADO:
  · a célula passa a ocupar DOIS Words — `S_LINHAS + 2·(i·ncols + j)` —, um
    para o numerador (baixo,alto) e outro para o denominador
  · o programa emitido copia DOIS Words por célula (emit_copia × 2)
  · OP_CMP e a comparação do WHERE passam a 16 bits: hoje é um OP_SUB de 8 e o
    bit de sinal por S_MASK; passa a ser o empréstimo do sub de 16
  · 23 sítios com S_LINHAS, 5 com S_DEN, o escritor, o leitor — e os medidores
    que lêem slots à mão (`mem_le(S_LINHAS + 0)`, `+2`, `+4`) mudam de endereço
Enquanto isso não for feito, o que não cabe é RECUSADO (§24) — o que não se pode
é guardar lixo em silêncio.


27. O DADO PASSA A DEZASSEIS BITS — e a metade que falta diz-se
=================================================================
O §26 provou a aritmética do andar; falta o caminho. O caminho tem DUAS metades,
e elas não custam o mesmo:

  a FRONTEIRA   escrever e ler uma célula — barata, e feita agora
  o AVALIADOR   o WHERE, que é POLINOMIAL dentro da ISA: o `S_MT` mascara o `.e`,
                os produtos são de átomo e a comparação é um OP_SUB de 8 com o
                bit de sinal. Alargar isto é alargar toda a avaliação — trio
                próprio, e não este.

FEITO
-----
  S_ALTO = 40960: o byte ALTO de cada célula num plano paralelo, como o
  denominador já vivia em S_DEN. **A Word da linha NÃO MUDA** — e é isso que
  torna a mudança barata: toda a aritmética emitida continua a ler exactamente
  o que sempre leu, e nenhuma das 23 ocorrências de S_LINHAS mexe.

    INSERT (255,1000) · (9,65535)   entram e voltam EXACTOS
    INSERT (65536,·) e (−1,·)       recusados, contados em cel_recusadas

E A METADE QUE FALTA DIZ-SE, EM VEZ DE SE FINGIR
------------------------------------------------
Um WHERE que cite uma coluna com valores acima de 255 é RECUSADO:

    column "grande" holds values above the 8-bit evaluator

contado em `cmp_recusadas`. O valor está guardado inteiro e o SELECT devolve-o;
o que não se faz é comparar METADE dele. Um banco que responde à toa é pior que
um que diz o que não sabe.

  medidor  banco/sql.c: 65535 encosta e volta, 65536 e −1 recusados, o WHERE na
           coluna ESTREITA corre e na LARGA é recusado — os dois lados
  gume     o byte alto não guardado → cai · o leitor sem compor → cai · a
           comparação sem recusar → cai · o envelope de volta a 255 → cai

O TRIO SEGUINTE — e o plano que eu tinha escrito estava ERRADO
--------------------------------------------------------------
Escrevi aqui «o `S_MT` deixa de mascarar o `.e` no caminho das colunas
inteiras», como se o segundo átomo estivesse livre. NÃO ESTÁ. Fui ler o
`emit_mul_zeck` e o `.e` é o REGISTO DE TRABALHO DO MULTIPLICADOR:

  a ISA não tem MUL. `n·x` faz-se por Zeckendorf — todo inteiro é soma de
  Fibonacci não consecutivos — e cada F(k) é `GOLD^(k−1)`, com
  GOLD = (a,b) ↦ (a+b, a). Parte-se de (x, 0) e o `.e` carrega F(k−1)·x.
  O `S_MT` limpa o `.e` ANTES dos deslocamentos e DEPOIS deles, e é por isso
  que ele está lá — não é desperdício, é o estado a ser reposto a zero.

Logo alargar o avaliador NÃO é tirar uma máscara. É:

  · o valor passa a ocupar DOIS Words, e o GOLD tem de deslocar em 16 bits —
    a mesma dobra do §26 aplicada ao rei, não à soma
  · o acumulador cresce para 32: o produto de dois valores de 16 pede-o, e é
    onde a torre volta a dobrar OUTRA VEZ
  · OP_ADD/OP_SUB ficam COMPONENTE A COMPONENTE — o catálogo guarda
    {ncols, nrows} numa Word e o `nrows++` soma 1 ao `.e`; com transporte a
    atravessar, um nrows de 255 a passar a 256 subiria para o ncols. O par e o
    número são leituras DIFERENTES da mesma Word, e por isso pedem instruções
    diferentes (OP_ADD16 e companhia), não uma troca do OP_ADD.

E NÃO SE ACRESCENTAM OS OPCODES ANTES DE HAVER QUEM OS EMITA. Escrevi-os,
liguei-os ao despacho, e tirei-os: sem um `emit` que os use são um ramo que
ninguém corre — a `ula_add16` e companhia ficam, porque essas TÊM utilizador (o
medidor do §26). O andar existe e está provado; o que falta é o caminho, e o
caminho é o avaliador inteiro.


28. A DOBRA DO REI — GOLD em dezasseis bits
=============================================
O §26 dobrou a SOMA (o vai-um atravessa o átomo). Este dobra o REI, que é o que
o avaliador precisa: a ISA não tem MUL, e `n·x` faz-se por ZECKENDORF —

    todo inteiro é soma de Fibonacci NÃO consecutivos, de um único jeito
    F(k) é uma potência do rei:  GOLD = (a,b) ↦ (a+b, a),  σ² = σ + 1
    de (x,0):  (x,x) → (2x,x) → (3x,2x) → (5x,3x) → …   k passos dão F(k+1)·x

Em oito bits o estado do rei É a Word — `a` no `.total`, `b` no `.e` — e é
exactamente por isso que o segundo átomo não está livre (§27).

FEITO
-----
  G16 {a,b}      o estado do rei um andar acima: um PAR de valores de 16 bits
  gold16         (a,b) ↦ (a+b, a), com o `+` a ser `ula_add16` — o vai-um
                 atravessa o átomo, e o que passa do andar DIZ-SE
  fib_vezes16    F(k+1)·x por k deslocamentos, de (x,0)
  mul16_zeck     n·x = Σ F(k_i)·x, o mesmo desenho do `emit_mul_zeck` um andar
                 acima; custo ~log_φ(n), não n

  medidor  o rei É Fibonacci nos quinze primeiros · 387 produtos varridos, 336
           acima de 255 e 17 ACIMA DE 65535 — e todos os que passam do tecto
           dizem-no · E O GUME: 3·100 dá 44 no rei de oito e 300 aqui
  gume     o GOLD sem deslocar (b'=b) → 326 de 387 caem · o Zeckendorf com i em
           vez de i+1 → 312 · o transbordo do gold16 perdido → 2

E UMA ARMADILHA DO MEU PRÓPRIO MEDIDOR, que vale mais que o resto: a primeira
varredura ia até n ≤ 40, x ≤ 300 — produto máximo 12000, LONGE do tecto de
65535. O ramo do transbordo NUNCA CORRIA, e por isso tirar a bandeira do andar
não derrubava nada. Não era guarda redundante nem ramo morto: era o REGIME do
meu varrimento a não conter o defeito. Subiu para 300·300 = 90000, e a mutação
passou a cair. E a exigência ficou `acima > 0` — que o ramo é VISITADO —, não o
17 que hoje sai: pôr ali o número medido era escrever o resultado dentro da
medição.

O QUE FALTA PARA O AVALIADOR (as duas peças que sobram)
--------------------------------------------------------
  · o valor em DOIS Words no caminho emitido, e o GOLD da ISA a deslocar sobre
    esse par — a `gold16` é a lei; falta o `emit`
  · o acumulador em 32: `c_i·x_i` com c_i e x_i de 16 bits pede-o, e é onde a
    torre dobra outra vez (a mesma conta, um andar acima)
  · e OP_ADD/OP_SUB ficam componente a componente — o catálogo guarda
    {ncols, nrows} numa Word e o `nrows++` soma ao `.e`


29. O AVALIADOR NO ANDAR DE CIMA — o WHERE compara dezasseis bits
==================================================================
O §27 guardava dezasseis bits e RECUSAVA compará-los; o §28 provou o rei. Aqui
o átomo LINEAR passa a correr no andar de cima, e o de oito fica intacto ao lado.

COMO, e sem uma instrução nova para montar
------------------------------------------
  emit_valor16   o valor está em dois sítios (o baixo na linha, o alto em
                 S_ALTO). Junta-se numa Word: TROCA leva (alto,0) a (0,alto) e o
                 OP_ADD — COMPONENTE A COMPONENTE, que aqui é exactamente o que
                 se quer — soma-lhe (baixo,0). Fica {baixo, alto}.
  OP_ADD16/SUB16/CMP16   a Word lida como UM número. O OP_ADD fica como estava:
                 o catálogo guarda {ncols, nrows} e o `nrows++` soma ao `.e`.
  emit_mul_zeck16  o rei de 16 NÃO é opcode — GOLD = (a,b) ↦ (a+b, a) sobre dois
                 slots são um ADD16 e uma cópia
  emit_teste16   o sinal é o bit 15: máscara {0, 0x80} em S_MASK16

E O ENVELOPE DA COMPARAÇÃO NÃO É O DO ARMAZENAMENTO
----------------------------------------------------
A célula guarda 0..65535 e o SELECT devolve-o. A comparação decide pelo SINAL da
diferença, logo pede que a FORMA INTEIRA caia em 0..32767. Três coisas ficam de
fora, cada uma com o seu motivo escrito:

    grau >= 2               um produto de 16×16 pede 32 — a torre dobra outra vez
    valor > 32767           o par lê-se NEGATIVO (`50000 < 100` dava verdadeiro)
    2·x com x até 32767     a FORMA estoura, mesmo com a coluna a caber

  E o majorante da forma não soma magnitudes: separa o MÁXIMO do MÍNIMO, senão
  `medio − 100` com medio a 32767 era recusado — e ali a conta dá 32667.

O QUE A LIGAÇÃO PONTA A PONTA APANHOU (outra vez)
--------------------------------------------------
`UPDATE ... SET v = 30000` escrevia só o átomo BAIXO e o alto ficava do valor
ANTERIOR: sobre um v de 1000 dava 29952 — a linha errada no disco, calada.
Nenhuma asserção o via. S_VA guarda o átomo alto do valor do SET e o emitido
copia os dois.

FALTA

30. O PRODUTO, E O ANDAR ESCOLHE-SE PELA FORMA
================================================
O PRODUTO SAI DA CADEIA, NÃO DE UM IDIOMA DE MÁQUINA. Fui ler os papers antes de
escrever, e a última linha do `naturais.tex` thm:transporte diz-o:

    «as duas operações que a iteração usa são a soma e o produto de 𝔽₂, as
     únicas primitivas de um bit; O PRODUTO DE ℕ SEGUE POR DESLOCAMENTO E SOMA»

e o lem:desloc dá a outra metade: multiplicar pelo gerador da dobra É deslocar,
x⊗σ = 2^w·x. Então

    x·y = Σ_i  y_i · (x << i)     com  x<<1 = x + x  (ADD16)  e  y_i = AND

  emit_mul16   dezasseis passos, o `<<` é `x+x` e o bit do multiplicador é um AND

               escrevem-se ao COMPILAR e o programa corre depois
  rascunho     o átomo passou de 12 a 48 slots (ATOMO_SLOTS): 4096 + 16·48 =

E O DEFEITO QUE ISTO DESTAPOU — ANTERIOR A TUDO ISTO

`c0 + Σ c_i·x_i` tem de caber em ±127. Com a = 100 e b = 50 o `a*b` dá 5000, e

    WHERE a*b > 1000   devolvia (3,7) e (150,2) — as duas que NÃO casam —

Nenhuma asserção o via porque as tabelas dos medidores têm valores pequenos e o

    cabe em ±127     → o andar de oito, byte a byte como sempre foi
    cabe em ±32767   → o andar de dezasseis
    o resto          → RECUSADO, com o motivo escrito

31. A MARCA ESTÁ NO AMBIENTE — a aranha estigmérgica, e o banco é um dos agentes
==================================================================================

O algoritmo está em `arquitetura.tex` §sec:aranha, thm:multiplicidade:

  cláusula 3   «A memória NÃO pertence ao agente. A escrita incremental
                G_{t+1}(x) = G_t(x) + 1_{x=π(t)} materializa no espaço tudo o que
                distingue região já percorrida de região nova. O agente NÃO
                conserva a sequência π(0),…,π(t).»
  cláusula 4   «SENTIR É LER G.»
  §sec:pecas   «o agente (autómato, tradutor, BANCO, aranha estigmérgica) não

                leitura/escrita produz a geometria global.»

  S_COLMAX  uma marca por coluna. A ESCRITA deixa-a (INSERT e UPDATE), a leitura

  não desce  um valor menor não a baixa, e o DELETE também não — o traço não se

  base antiga  sem marca e com linhas, reconstrói-se UMA vez e fica escrita —

  gume     o INSERT sem marcar → cai · o UPDATE sem marcar → cai · a marca a

32. O DRAGÃO E O INVERSO — o byte alto É a folha, e tem teorema
=================================================================
Li o dragão e o inverso da aranha, e o que eu tinha construído já lá estava
descrito. Eu é que não lhe tinha dado o nome.

A DOBRA (thm:multiplicidade)
----------------------------
A célula de oito bits é a realização

    π : valor ⟼ célula,     célula = valor mod 256

e ela DOBRA: 44, 300, 556 e 812 caem TODOS na mesma célula. Isso é literalmente
a identificação `i ∼ j ⟺ π(i) = π(j)`, e G(célula) = |π⁻¹| conta quantos valores
lá colapsam. O `INSERT ... VALUES (500)` a guardar 244 NÃO era um defeito de
tipo: era a FIBRA a ser perdida na projecção — `algebrico thm:metrica`, |det|=1
conserva a MEDIDA e não o percurso, «a pata some na marca».

O LEVANTAMENTO (thm:aranha-inversa)
------------------------------------
    π̃(v) = (π(v), k(v))      com k = o byte ALTO

«Não inventa geometria nova: desfaz a identificação i∼j que o dragão fez na
grade. A métrica unimodular continua a governar a base; a folha é a fibra que
|det| = 1 não via.»

  (1) INJECTIVIDADE  G̃ ≡ 1 — os quatro pares (baixo,alto) são únicos e os quatro
                     valores voltam DISTINTOS pelo SELECT
  (2) PROJECÇÃO      pr₁ ∘ π̃ = π — o byte baixo guardado é exactamente v mod 256,
                     que é a célula que uma base antiga tem
  (3) DOBRA REAL     na BASE os quatro colapsam numa célula só, G = 4

E A RECUSA ACIMA DE 32767 É A OUTRA METADE DO MESMO TEOREMA: o avaliador decide
na BASE, e a base não vê a folha.

E UMA TAUTOLOGIA MINHA, apanhada a tempo: escrevi a medida primeiro em
aritmética de C — `(v&255) | ((v>>8)<<8) == v` varrido em 65536 valores, 0
falhas. É uma IDENTIDADE, não uma medição: passaria com o banco desligado. A
medida tem de ir ao .mem ver o que as células GUARDAM, e é o que faz agora.

  gume   a folha não escrita → cai (e o mutante imprime [44][44][44][44], a dobra

§39 — O ESPAÇO DEFINIDO, O TEMPO DERIVADO, E A MÉTRICA QUE O CURVA
==================================================================
Ordem: «define o espaço onde isso ocorre, é o espaço inicial da construção dos
naturais.tex F_n = F_{n-1} + F_{n-1}*»; «o tempo sai do operador — quem é o
operador? É VOCÊ que está a operar o sistema. Mas de que forma? Por VARIAÇÃO,
DERIVADA, óbvio, porque se nada variar você não vê nada»; «qual a melhor forma
de variar? A mais fácil — a aranha sobe sozinha, então basta controlar UM
parâmetro numa recta. O TEMPO É A TAXA com que você varia o parâmetro»; depois
«o tempo é a VARIAÇÃO NA TAXA DE DOBRAS quando salta de um vértice pro outro»;
«dá a métrica g na variação quadrática, dτ² = g_uv...»; e «o tempo passa
diferente em cada ponto do espaço — generaliza a métrica».

O ESPAÇO NÃO FOI ESCOLHIDO (§AN19). A construção dos naturais dá
    F_{2w} = F_w ⊕ σF_w,  σ² = σ + λ
e em característica 2 a soma é o XOR coordenada a coordenada. Logo, COMO GRUPO
ADITIVO, F_{2w} É (ℤ/2)^{2w}, e o seu grafo com os geradores canónicos é o
HIPERCUBO Q_{2w}: duas cópias de F_w ligadas pelo emparelhamento σ. Medido em
quatro andares. É a MESMA dobra T + T* em três sítios — a curva, a torre, e o
grafo onde a transformada vive.

O TEMPO DERIVA-SE, EM TRÊS PASSOS
  1. opera-se por VARIAÇÃO. O operador é o deslocamento S; μ = 1 − S é a
     DERIVADA discreta e ζ = (1−S)⁻¹ integra. Se nada varia nada se vê, e
     mede-se: a trajectória constante tem μπ ≡ 0 e o campo colapsa numa célula.
  2. a variação mais barata é UM parâmetro numa recta — a aranha sobe sozinha.
  3. o tempo é a TAXA DE DOBRAS por salto: d(t) = 1 quando se chega a célula já
     marcada, D = d*ζ, e μD = d com resíduo 0.

E O NÚMERO DEPENDE DA RÉGUA (§AN20). O mesmo percurso:
    grade    1024 de comprimento, salto 1 sempre, 1 comprimento distinto
    árvore   12288,  saltos de 2 a 2048, ONZE comprimentos distintos
A taxa de dobras por unidade é 335/1024 numa e 335/12288 na outra. As duas são
réguas do MESMO objecto — mesma ordem de índices, nenhum salto colapsado. O
isomorfismo é entre as RÉGUAS, não entre os números.

A MÉTRICA COMO FORMA QUADRÁTICA (§AN21): dτ² = g_uv dx^u dx^v, simétrica, não
degenerada, e INTEIRA por aresta. Três g sobre o mesmo percurso dão 1024, 2560 e
2048. E UMA distingue-se: com g = I toda aresta dá dτ² = 1, logo τ = N — O TEMPO
PRÓPRIO É O PARÂMETRO. É por isso que a grade é a régua barata: variar o
parâmetro e andar no espaço são a mesma conta.
  · e o PERCURSO SÓ SONDA A DIAGONAL DE g: numa aresta dx tem uma componente só,
    logo o termo cruzado nunca é medido. Preciso de um salto diagonal — que pelo
    §AN18 não é aresta. Medido: aresta (1,0) dá 2 com e sem; diagonal (1,1) dá 6
    contra 4, e a diferença é a soma dos termos fora da diagonal.

A GENERALIZAÇÃO (§AN22): g depende do PONTO, e quem a faz variar é o campo:
    g_uv(x) = G(x)·h_uv   ⟹   dτ² = G(x)·h_ii  numa aresta
O TEMPO PRÓPRIO DE UM SALTO É A MULTIPLICIDADE DA CÉLULA DE CHEGADA. Onde a
trajectória já passou, o tempo passa outro — a memória, ao ficar no espaço,
CURVA-O. Medido: o dragão tem g variável e τ = 1694 ≠ N = 1024; a recta axial
tem G ≡ 1, g constante e τ = N. A métrica plana é o caso sem dobra.

E DAÍ SAI O PASSO 3 DO CICLO: o gradiente escolhe o vizinho de menor G, que com
h = id é o de menor dτ² — É UMA GEODÉSICA. A aranha não delibera nem optimiza:
vai por onde o tempo próprio é mínimo. A hipótese da isotropia não é decoração e
mede-se com contra-exemplo: com h anisotrópica as duas escolhas DIVERGEM
(vizinho 3 contra 2, e 5 contra 4).

DUAS ASSERÇÕES MINHAS QUE O GUME APANHOU
  · comparei G com G·1 e chamei-lhe geodésica: era comparar G consigo mesmo.
  · «o termo cruzado DIFERE no salto diagonal» passava com qualquer valor
    errado. Agora exige os valores DERIVADOS de g: a forma completa é a soma de
    todas as entradas, a truncada é o traço, e a diferença é o que está fora.

§41 — A REESCRITA CONSTRUTIVA: espaço vectorial, dual, e as duas álgebras
=========================================================================
Ordem: «agora que tem a construção com a base ortonormal, reescreve a
transformada, a convolução e a deconvolução DESCENDO construtivamente na base do
espaço, em funções genéricas, tudo no discreto — e dá a linguagem da álgebra
linear: espaço vectorial e espaço dual».

DOIS ESPAÇOS EM ANDARES DIFERENTES, e confundi-los é o erro fácil (§AN26):
  EM BAIXO   X = F_{2^m} sobre 𝔽₂, dim m, base {e_k = 2^k} — o espaço ONDE a
             aranha anda, e as direcções de aresta de Q_m SÃO essa base (§AN24)
  EM CIMA    V = ℤ^X sobre ℤ, dim n = 2^m, base {δ_x} — o espaço das FUNÇÕES,
             onde o campo G vive como VECTOR: G = Σ_x G(x)·δ_x
O que eu chamava «a ida é uma soma de Diracs» tem agora o nome próprio: são as
COORDENADAS de G na base canónica.

A DESCIDA, e cada passo obriga o seguinte:
  1. a operação de X estende-se a V por bilinearidade: δ_a * δ_b = δ_{a⊕b}
     ⟹ V É O ANEL DE GRUPO ℤ[X], e a convolução é o seu produto
  2. os operadores C_f(g) = f*g COMUTAM (C_f C_g = C_{f*g})
  3. ⟹ existe base própria COMUM. A pergunta deixa de ser «que transformada
     escolher» e passa a ser «qual é essa base» — e é única a menos de escala
  4. são os CARACTERES: C_f·χ_k = f̂(k)·χ_k, e o VALOR PRÓPRIO é a coordenada dual
  5. ⟹ a transformada não é operação nova: é a MUDANÇA DE BASE de {δ_x} para
     {χ_k}, com matriz H_{kx} = χ_k(x) e F(δ_a)_k = χ_k(a)
  6. H² = n·I ⟹ F∘F = n·id, que é a BIDUALIDADE V** ≅ V em coordenadas; e é por
     X ser AUTODUAL pela forma ⟨·,·⟩ que os caracteres se indexam por X
  7. a convolução vira produto ponto a ponto, a deconvolução vira divisão
     diagonal, e a degenerescência tem nome: C_f TER NÚCLEO

E A ADJACÊNCIA É UMA CONVOLUÇÃO — o espectro do grafo passa a COROLÁRIO. Com
α = Σ_i δ_{e_i} a indicadora das direcções, A = C_α, logo
     A·χ_k = α̂(k)·χ_k = (m − 2|k|)·χ_k.
Os caracteres não foram escolhidos, e agora vê-se DUAS vezes porquê.

O OUTRO LADO, E A ESTRUTURA É OPOSTA (§AN27). Em W = ℤ^I com base {δ_t}, o
deslocamento S é a matriz SUBDIAGONAL de uns:
  · NILPOTENTE de índice exactamente dim W (medido: S¹² = 0, e 12 é o mínimo)
  · único valor próprio 0, dim ker S = 1 — um BLOCO DE JORDAN, não diagonaliza
  · e é POR SER NILPOTENTE que 1 − S inverte, com a inversa a ser a série de
    Neumann FINITA Σ S^j — que é a triangular de uns, isto é, o ζ
NÃO HÁ CONVERGÊNCIA NENHUMA EM JOGO: há nilpotência. E daí a frase que fecha:
  no DOMÍNIO a inversão existe SEMPRE (nilpotência)
  no CONTRADOMÍNIO existe sse nenhum valor próprio se anula (diagonalização)
Duas álgebras lineares, dois motivos de invertibilidade, e as duas operações da
aranha uma em cada.
