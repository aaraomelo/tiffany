### 1. ⊕

**Definição matemática**  
- Algébrica: \( a \oplus b \) em \(\mathbb{F}_2\) (e coordenada a coordenada em \(\mathbb{F}_2^8\)).  
- Cisão: \(\pi: I \to X\), linha \(i\) do bitmap = coordenada \(i\) (arquitetura.tex).

**Função concreta**  
```c
// umbit.h
static V8 v_som(V8 a, V8 b){ return (V8)(a ^ b); }
static B  b_som(B x, B y){ return (B)(x ^ y); }
```
`palavra8.h`: `w8_xor = v_som` (marcado como ⊕).  
`corpo256.h`: “a ⊕ b = XOR, coordenada a coordenada”.

**Chamada pelo banco?**  
Sim, via ULA: `ula_xor` e `OP_XOR`.

**Primitiva da ISA?**  
Sim: `OP_XOR` existe e é executado.

**Sequência ISA?**  
Não necessária — é opcode direto.

**Teste executável?**  
Sim (`tests/neuronio.c` e medição de 256 bytes).

**Saída matemática igual?**  
Sim para a operação algébrica.

**Grau**  
- \( a \oplus b = a \operatorname{XOR} b \): **IDENTIDADE FORMAL**  
- Cisão \(\pi: I \to X\) como função explícita no banco: **NÃO DEMONSTRADA**  

(A operação ⊕ está realizada; a projeção \(\pi\) como entidade separada não aparece como chamada ou opcode no fluxo do banco.)

### 2. Σ

**Definições em jogo**  
A) `popcount(byte)`  
B) \(\sum_i \mathrm{bit}_i\)  
C) \(\Sigma_x G(x) = |I|\)  
D) Σ como operação semântica do kernel

**Função concreta**  
```c
// umbit.h
static int v_peso(V8 a){
    int n = 0;
    for(int i = 0; i < 8; i++) n += (a >> i) & 1;
    return n;
}
```
Comentários e `tests/neuronio.c` identificam isso com Kirchhoff / Σ.

**Chamada pelo banco?**  
Sim, como função C de medição (`bits_conta` / `v_peso`).

**Primitiva da ISA?**  
**Não.** Não existe `OP_POPCOUNT` nem `OP_SUM`.

**Sequência concreta de ADD/AND/XOR/SUB que implementa popcount como programa da ISA?**  
**NÃO DEMONSTRADA.**  
Nenhum programa ISA documentado ou testado que realize o popcount a partir das primitivas da ULA.

**Teste da sequência?**  
Não existe.

**Grau**  
- A e B (popcount / soma de bits): **REALIZAÇÃO OPERACIONAL** (função C verificável).  
- C (\(\Sigma_x G(x) = |I|\)): **CORRESPONDÊNCIA ESTRUTURAL** (mesma definição, mas medida fora da máquina).  
- D (Σ como operação do kernel executável pela ISA): **NÃO DEMONSTRADA**.

**Conclusão precisa**  
Σ possui implementação concreta em C,  
mas sua realização como programa da ISA **não foi demonstrada**.

### 3. ⊗ — GATO

**Definição matemática**  
\[
G(a,b) = (a \oplus b,\ a)
\]
(em \(\mathbb{F}_2\); generalização \(cifra_{an}(w,n) = (n\cdot total + e,\ total)\)).

**Função concreta**  
```c
// umbit.h
static void b_gato(B *c0, B *c1){
    B n0 = b_som(*c0, *c1), n1 = *c0;
    *c0 = n0; *c1 = n1;
}

// erg.c
static Word gato_an(Word w, int n, int para_tras){ ... }
static Word cifra_an(Word w, int n){ return gato_an(w, n, 0); }
```
Execução:
```c
case OP_GOLD: r->A = cifra_an(r->A, 1); r->R = r->A; break;
```

**Entrada → função → saída → comparação**  
Entrada \((total, e)\).  
`cifra_an(..., 1)` produz \((total + e,\ total)\).  
Em \(\mathbb{F}_2\) (n=1) coincide exatamente com \(G\).  
Comentário no código: verificado `decifra(cifra(w)) = w` em 5776 casos.

**OP_GOLD é instrução ISA?**  
**Sim.** Está na tabela de opcodes da ISA do `erg.c` e é despachado pelo interpretador como qualquer outro opcode.

**Sequência de XOR/AND/ADD/SUB/MOVE que reproduz o gato?**  
Não documentada nem testada como programa composto.  
O gato é realizado **diretamente** pelo opcode `OP_GOLD`.

**Grau**  
**REALIZAÇÃO DIRETA** (opcode semântico da ISA).

### 4. ⊘ — ESQUILO

**Definição matemática**  
\[
E(u,v) = (v,\ u \oplus v)
\]
Inversa:
\[
E(G(a,b)) = (a,b),\quad G(E(u,v)) = (u,v)
\]

**Função concreta**  
```c
static Word decifra_an(Word w, int n){ return gato_an(w, n, 1); }
case OP_NEGRO_OURO: r->A = decifra_an(r->A, 1); r->R = r->A; break;
```
Também `OP_ESQUILO` / `corpo_gira(..., -1)` (rotação com sinal).

**Prova de inversão**  
Código afirma e mede: `decifra(cifra(w)) = w` e vice-versa (0 falhas em milhares de casos).

**Categoria**  
`OP_NEGRO_OURO` é **opcode da ISA** (mesma tabela que GOLD, ADD, XOR…).

**Sequência composta de primitivas básicas?**  
Não demonstrada. Realização é direta via opcode.

**Grau**  
**REALIZAÇÃO DIRETA** (opcode semântico da ISA) + identidade de inversão medida.

### 5. MOVE

**Definição no paper**  
\(\partial x = a + b - x\), com faces \(+1\) e \(-1\).

**Função concreta**  
```c
// erg.c
static unsigned MOVE_exec(Regs *r, unsigned pc, int sentido){
    unsigned slot = ...;
    if(sentido > 0){ r->B = r->A; r->A = mem_le(slot); }  // LOAD
    else           { mem_grava(slot, r->R); }              // STORE
    return pc;
}
```
LOAD e STORE são a mesma transferência com sinal.

**Identificação de a, b, x no estado da máquina**  
**Não encontrada.**  
Não há variáveis de estado nomeadas `a`, `b`, `x` tais que a transformação executada seja algebricamente \(x \mapsto a+b-x\).

**O que está demonstrado**  
+1 = leitura (mem → registrador)  
-1 = escrita (registrador → mem)  
Reversibilidade operacional via o par.

**Grau**  
**REALIZAÇÃO OPERACIONAL** da dualidade leitura/escrita.  
**NÃO** identidade formal \(\partial x = a+b-x\).

### 8. Aranha.c → Banco (L0…L7)

Classificação rigorosa (sem associação nominal):

| Lei | Classificação              | Evidência concreta |
|-----|----------------------------|--------------------|
| L0  | CORRESPONDÊNCIA CONCEITUAL | Nulos 0/FF e hash/endereçamento; nenhuma ponte matemática explícita de “divisão do zero” para o banco |
| L1  | CORRESPONDÊNCIA ESTRUTURAL | Dualidade aparece em gato/esquilo e sinal de MOVE; não é identidade formal de Poincaré |
| L2  | CORRESPONDÊNCIA ESTRUTURAL | Bidual via `corpo_gira` / ESQUILO; não prova \(K^{**}=K\) como teorema no banco |
| L3  | CORRESPONDÊNCIA CONCEITUAL | Sinais {+1,0,−1} existem; nenhuma ponte para o trial ternário |
| L4  | REALIZAÇÃO COMPOSTA        | Gato (`OP_GOLD`) realiza a dobra com |det|=1; mais forte que as demais |

| L6  | CORRESPONDÊNCIA ESTRUTURAL | `lei6_coincide` (XOR==AND em pontos); não é operação executada pelo banco |
| L7  | CORRESPONDÊNCIA ESTRUTURAL | Par (total, e) / Word_8²; estrutura presente, sem prova de “ligar sem fundir” como teorema |

Nenhuma das oito é **IDENTIDADE FORMAL** nem **REALIZAÇÃO DIRETA** completa no sentido de uma lei isolada virando um único mecanismo verificável de ponta a ponta.
